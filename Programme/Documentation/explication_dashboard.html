Connexion à l'ESP32

connect()
WebSocket UI

C'est la fonction centrale du dashboard. Elle lit l'adresse IP saisie par l'utilisateur, ouvre une connexion WebSocket persistante vers l'ESP32, et attache tous les handlers d'événements réseau.

Un WebSocket est différent d'une requête HTTP classique : la connexion reste ouverte en permanence dans les deux sens. L'ESP peut envoyer des données à tout moment sans que le navigateur les ait demandées, et inversement.

JavaScript connect() — ouverture de la connexion WebSocket 
function connect() {
  // 1. Lit l'IP saisie dans le champ texte (ex: "192.168.1.100")
  const ip = document.getElementById('ip-input').value.trim();

  // 2. Si une connexion existe déjà, on la ferme proprement avant d'en ouvrir une nouvelle
  if (ws) ws.close();

  log(`Connexion à ws://${ip}/ws ...`, 'entry');

  // 3. Ouverture du WebSocket
  //    Le protocole ws:// est le WebSocket non-chiffré (comme http:// vs https://)
  //    Le port 81 est celui sur lequel l'ESP32 écoute (séparé du port 80 HTTP)
  //    /ws est le chemin du endpoint WebSocket sur l'ESP
  ws = new WebSocket(`ws://${ip}:81/ws`);

  // 4. Événement : connexion établie avec succès
  ws.onopen = () => {
    setStatus(true);
    log('WebSocket connecté', 'entry');
    // Lance un ping toutes les 2 secondes pour mesurer la latence
    pingInterval = setInterval(sendPing, 2000);
  };

  // 5. Événement : connexion perdue (WiFi coupé, ESP redémarré, etc.)
  ws.onclose = () => {
    setStatus(false);
    clearInterval(pingInterval);   // Arrête les pings
    clearInterval(sendInterval);   // Arrête l'envoi des commandes moteur
    log('WebSocket déconnecté', 'err');
  };

  ws.onerror = () => log('Erreur WebSocket', 'err');

  // 6. Événement : message reçu de l'ESP32
  //    C'est ici que l'on trie les messages entrants selon leur type
  ws.onmessage = (e) => {
    try {
      const d = JSON.parse(e.data); // Décode le JSON reçu

      if (d.type === 'pong') {
        // Réponse à notre ping → calcul de la latence en ms
        document.getElementById('latency').textContent =
          (Date.now() - pingTime) + ' ms';
        return;
      }

      if (d.type === 'sensor') updateSensors(d); // Données MQ-9

    } catch(_) {} // Ignore les messages non-JSON
  };
}
Pourquoi le port 81 ?
L'ESP32 fait tourner deux serveurs en parallèle : un serveur HTTP sur le port 80 (pour une éventuelle page de statut), et le serveur WebSocket sur le port 81. Séparer les ports évite les conflits et simplifie le code côté ESP.
Cas d'échec fréquents
Si la connexion échoue immédiatement, vérifier : l'IP est-elle correcte ? L'ESP est-il sur le même réseau WiFi ? Le pare-feu Windows bloque-t-il le port 81 ?

Envoi d'une commande moteur

sendCmd(cmd)
WebSocket → ESP32 → PCA9685

C'est la fonction qui traduit un appui sur une flèche en mouvement réel des servos. Elle construit un message JSON et l'envoie via WebSocket à l'ESP32, qui l'interprète pour piloter le PCA9685.

JavaScript sendCmd() — envoi JSON vers l'ESP32 
function sendCmd(cmd) {
  // Vérifie que le WebSocket est ouvert (état 1 = OPEN)
  // États possibles : 0=CONNECTING, 1=OPEN, 2=CLOSING, 3=CLOSED
  if (ws?.readyState !== 1) {
    log('Non connecté', 'warn');
    return;
  }

  // Lit la valeur du slider de vitesse (0 à 100)
  const speed = parseInt(document.getElementById('speed').value);

  // Construit et envoie le message JSON
  //   type  → identifie le type de message (l'ESP le filtre sur ce champ)
  //   cmd   → la direction : "forward", "backward", "left", "right", "stop"
  //   speed → entier 0-100, l'ESP l'utilise pour calculer l'amplitude des mouvements
  ws.send(JSON.stringify({ type: 'cmd', cmd, speed }));

  log(`> CMD ${cmd.toUpperCase()} speed=${speed}`, 'cmd');
}

Le message JSON envoyé à l'ESP ressemble à ceci :

"type" string Toujours "cmd" pour une commande moteur
"cmd" string "forward" | "backward" | "left" | "right" | "stop"
"speed" int 0–100 Vitesse — mappé côté ESP sur le délai entre les frames de marche
Pourquoi envoyer en boucle ?
sendCmd est appelée une première fois dès l'appui, puis répétée toutes les 150 ms par startCmd() tant que le bouton est maintenu. Sans cette répétition, un seul paquet perdu sur le WiFi suffirait à bloquer le robot en pleine marche.

Gestion de l'appui sur les boutons

startCmd(cmd, el) & stopCmd()
UI WebSocket

Ces deux fonctions forment une paire. startCmd démarre le mouvement quand on appuie, stopCmd l'arrête quand on relâche. Ce comportement "maintenu = en mouvement" imite une télécommande physique.

JavaScript startCmd() — déclenché au mousedown / touchstart 
function startCmd(cmd, el) {
  // Évite de relancer si la même commande est déjà active
  if (currentCmd === cmd) return;

  stopCmd(); // Nettoie toute commande précédente

  currentCmd = cmd;
  el.classList.add('pressed');   // Effet visuel sur le bouton
  activateLegs(cmd);             // Anime les membres sur la silhouette SVG

  sendCmd(cmd);  // 1er envoi immédiat

  // Puis on continue d'envoyer toutes les 150 ms tant que le bouton est maintenu
  // Ainsi l'ESP reçoit un flux continu et peut continuer la séquence de marche
  if (cmd !== 'stop') {
    sendInterval = setInterval(() => sendCmd(cmd), 150);
  }
}
JavaScript stopCmd() — déclenché au mouseup / mouseleave / touchend 
function stopCmd() {
  if (!currentCmd || currentCmd === 'stop') return;

  clearInterval(sendInterval); // Arrête la répétition des commandes

  // Retire l'effet visuel de tous les boutons
  document.querySelectorAll('.btn').forEach(b => b.classList.remove('pressed'));

  // Remet tous les membres en position passive sur la silhouette
  document.querySelectorAll('.leg').forEach(l => {
    l.classList.remove('active');
    l.classList.add('leg-idle');
  });

  document.getElementById('current-cmd').textContent = 'EN ATTENTE';
  currentCmd = null;

  sendCmd('stop'); // Envoie "stop" à l'ESP pour qu'il immobilise les servos
}

// Branchement des événements sur chaque bouton du D-pad
document.querySelectorAll('.btn[data-cmd]').forEach(btn => {
  const cmd = btn.dataset.cmd;

  // mousedown = appui souris | touchstart = appui tactile
  btn.addEventListener('mousedown',  e => { e.preventDefault(); startCmd(cmd, btn); });
  btn.addEventListener('touchstart', e => { e.preventDefault(); startCmd(cmd, btn); }, { passive: false });

  // Sauf STOP : celui-là on veut qu'il reste actif même après le relâchement
  if (cmd !== 'stop') {
    btn.addEventListener('mouseup',    () => stopCmd());
    btn.addEventListener('mouseleave', () => stopCmd()); // Si la souris glisse hors du bouton
    btn.addEventListener('touchend',   () => stopCmd());
  }
});
Pourquoi mouseleave ?
Si l'utilisateur appuie sur une flèche puis fait glisser sa souris hors du bouton sans relâcher le clic, mouseup ne se déclenche jamais. mouseleave attrape ce cas et envoie quand même stop à l'ESP — sinon le robot continuerait indéfiniment.

Réception des données MQ-9

updateSensors(d)
Données reçues de l'ESP32 Mise à jour UI

Cette fonction est appelée automatiquement à chaque fois que l'ESP envoie un paquet de type "sensor" via WebSocket, soit environ toutes les 2 secondes. Elle met à jour tous les éléments visuels du panneau capteur.

Le JSON reçu de l'ESP a cette structure :

"type" string Toujours "sensor" pour ce type de paquet
"raw" int 0–4095 Valeur brute ADC lue sur GPIO34 (résolution 12 bits)
"voltage" float Tension en volts calculée depuis raw (0–3.3V)
"rs" float Résistance interne du capteur RS en kΩ
"ratio" float Rapport RS/RO — utilisé dans la courbe datasheet
"ppm" float Estimation CO en ppm calculée par l'ESP
"alert" bool true si le seuil digital (GPIO32) est dépassé
JavaScript updateSensors() — traitement complet des données capteur 
function updateSensors(d) {
  const ppmEl = document.getElementById('ppm');
  const ppm   = parseFloat(d.ppm) || 0;

  // ── Mise à jour des valeurs textuelles ──────────────────
  document.getElementById('raw').textContent =
    d.raw ?? '—';                            // Valeur brute ADC

  document.getElementById('voltage').textContent =
    d.voltage ? parseFloat(d.voltage).toFixed(2) : '—';  // 2 décimales

  ppmEl.textContent = ppm.toFixed(1);        // 1 décimale pour les PPM

  // ── Barre de progression PPM ─────────────────────────────
  // MAX_PPM = 1000 : au-delà de 1000 ppm, la barre est pleine
  // La barre utilise un dégradé CSS vert→bleu→orange→rouge
  // La couleur affichée dépend donc de la largeur (position dans le dégradé)
  const pct = Math.min(ppm / MAX_PPM * 100, 100);
  document.getElementById('ppm-bar').style.width = pct + '%';

  // ── Couleur de la valeur PPM selon le niveau de danger ───
  // Seuils : WARN_PPM = 200 ppm, DANGER_PPM = 500 ppm
  if (ppm >= DANGER_PPM)
    ppmEl.className = 'metric-val danger';  // Rouge + animation clignotante
  else if (ppm >= WARN_PPM)
    ppmEl.className = 'metric-val warn';    // Orange
  else
    ppmEl.className = 'metric-val';         // Bleu normal

  // ── Badge d'alerte digital ───────────────────────────────
  // d.alert = true quand GPIO32 passe LOW
  // (le comparateur interne du module MQ-9 a détecté un dépassement de seuil)
  const badge = document.getElementById('alert-badge');
  const txt   = document.getElementById('alert-text');
  if (d.alert) {
    badge.className = 'alert-badge danger';  // Rouge clignotant
    txt.textContent = 'ALERTE GAZ';
  } else {
    badge.className = 'alert-badge';         // Vert normal
    txt.textContent = 'NORMAL';
  }

  // ── Indicateur sur la silhouette SVG ─────────────────────
  // Le petit cercle sur le corps du robot change de couleur
  // vert = normal, rouge = alerte
  const mq9dot = document.getElementById('mq9-dot');
  mq9dot.setAttribute('stroke', d.alert ? '#ff3366' : '#00ff88');
}
Comment ce JSON arrive-t-il ici ?
Dans connect(), le handler ws.onmessage reçoit tous les messages de l'ESP. Il parse le JSON et regarde le champ type : si c'est "sensor", il appelle updateSensors(d). Si c'est "pong", il calcule la latence. C'est un système de routage de messages simple mais efficace.

Animation de la silhouette robot

activateLegs(cmd)
UI uniquement — purement visuel

Cette fonction ne communique pas avec l'ESP — elle est purement visuelle. Elle met en évidence les membres du robot sur le SVG pour refléter le mouvement en cours. La correspondance commande → membres actifs suit le pattern de trot diagonal utilisé dans le code C++.

JavaScript activateLegs() — mise en évidence visuelle des membres actifs 
// Table de correspondance : commande → IDs des éléments SVG à activer
// Trot diagonal : FR+BL ou FL+BR travaillent ensemble
// (comme un vrai quadrupède — diagonalement opposés)
const LEG_MAP = {
  forward:  ['leg-fr', 'leg-bl'], // Antérieur droit + Postérieur gauche
  backward: ['leg-br', 'leg-fl'], // Postérieur droit + Antérieur gauche
  left:     ['leg-fl', 'leg-bl'], // Les deux membres gauches
  right:    ['leg-fr', 'leg-br'], // Les deux membres droits
  stop:     []                       // Aucun
};

function activateLegs(cmd) {
  // Remet tous les membres en état "passif" (opacity 35%)
  document.querySelectorAll('.leg').forEach(l => {
    l.classList.remove('active');
    l.classList.add('leg-idle');
  });

  // Active les membres correspondants (opacity 100%)
  const active = LEG_MAP[cmd] || [];
  active.forEach(id => {
    const el = document.getElementById(id);
    if (el) {
      el.classList.add('active');
      el.classList.remove('leg-idle');
    }
  });

  // Met à jour le texte de commande en cours en bas de la vue robot
  document.getElementById('current-cmd').textContent =
    cmd === 'stop' ? 'ARRÊT' : cmd.toUpperCase();
}

Mesure de la latence réseau

sendPing()
WebSocket aller-retour

Toutes les 2 secondes, le dashboard envoie un ping à l'ESP. L'ESP répond immédiatement par un pong. La différence de temps entre l'envoi et la réception donne la latence aller-retour (RTT) en millisecondes — une bonne indication de la qualité de la liaison WiFi.

JavaScript sendPing() — mesure de latence aller-retour 
function sendPing() {
  if (ws?.readyState !== 1) return;

  pingTime = Date.now();  // Mémorise l'heure d'envoi en ms
  ws.send(JSON.stringify({ type: 'ping' }));
  // L'ESP répond {"type":"pong"} → ws.onmessage calcule Date.now() - pingTime
}

// Côté ESP (pour référence) :
// if (strcmp(t, "ping") == 0) {
//   wsServer.sendTXT(num, "{\"type\":\"pong\"}");
// }
Valeurs de référence
En WiFi local, une latence inférieure à 20 ms est excellente. Entre 20 et 80 ms, le contrôle reste fluide. Au-delà de 100 ms, on commence à percevoir un décalage entre l'appui et le mouvement.

Journal des événements

log(msg, cls)
UI

Affiche un message horodaté dans la zone de log en bas du dashboard. Le paramètre cls détermine la couleur de la ligne.

JavaScript log() — journalisation horodatée 
function log(msg, cls = 'entry') {
  const el  = document.getElementById('log');
  const now = new Date().toLocaleTimeString('fr-FR'); // ex: "14:32:05"

  // Classes CSS disponibles :
  //   'entry' → texte blanc (événements généraux)
  //   'cmd'   → texte bleu cyan (commandes envoyées)
  //   'warn'  → texte orange (avertissements)
  //   'err'   → texte rouge (erreurs)
  el.innerHTML += `<div class="entry ${cls}">[${now}] ${msg}</div>`;

  el.scrollTop = el.scrollHeight; // Auto-scroll vers le bas

  // Limite à 40 lignes pour ne pas surcharger le DOM
  while (el.children.length > 40) el.removeChild(el.firstChild);
}

Contrôle au clavier

Événements keydown / keyup
UI

En plus des boutons à l'écran, le dashboard écoute les touches du clavier. La logique est identique : keydown démarre la commande, keyup l'arrête — exactement comme mousedown / mouseup.

JavaScript Mapping clavier → commandes 
const KEY_CMD = {
  ArrowUp':    'forward',
  'ArrowDown':  'backward',
  'ArrowLeft':  'left',
  'ArrowRight': 'right',
  ' ':          'stop'     // Barre espace
};

document.addEventListener('keydown', e => {
  const cmd = KEY_CMD[e.key];
  if (!cmd) return;
  e.preventDefault(); // Empêche le scroll de la page avec les flèches
  const btn = document.querySelector(`.btn[data-cmd="${cmd}"]`);
  if (btn) startCmd(cmd, btn); // Réutilise exactement la même logique que les boutons
});

document.addEventListener('keyup', e => {
  const cmd = KEY_CMD[e.key];
  if (cmd && cmd !== 'stop') stopCmd();
});

Résumé — flux complet d'un mouvement

  1. 1
    L'utilisateur appuie sur la flèche avant (souris, tactile ou touche ↑)
  2. 2
    startCmd('forward', btn) est appelée → le bouton devient bleu, la silhouette SVG allume FR+BL
  3. 3
    sendCmd('forward') envoie {"type":"cmd","cmd":"forward","speed":50} via WebSocket
  4. 4
    Un setInterval répète sendCmd toutes les 150 ms tant que le bouton est maintenu
  5. 5
    L'ESP reçoit chaque paquet → onWsEvent() → met à jour currentCmd = CMD_FORWARD
  6. 6
    Dans le loop() de l'ESP, tickGait() avance d'une frame de marche toutes les X ms (dépend de la vitesse)
  7. 7
    Le PCA9685 reçoit les nouvelles positions via I2C → les 8 servos bougent
  8. 8
    L'utilisateur relâche → stopCmd() → envoie {"type":"cmd","cmd":"stop"} → l'ESP appelle standStill()
