Connexion au robot

connect()
WebSocketUI

Ouvre une connexion WebSocket persistante vers l'ESP32-S3. L'IP est saisie dans le champ texte du dashboard. La connexion reste ouverte en permanence dans les deux sens : l'ESP peut envoyer les données MQ-9 à tout moment sans que le navigateur les ait demandées.

JavaScriptconnect() — ouverture WebSocket et handlers
function connect() {
  const ip = document.getElementById('ip-input').value.trim();
  if (ws) ws.close();   // Ferme l'ancienne connexion si elle existe

  // Port 81 = WebSocket ESP32 (séparé du port 80 HTTP)
  // Pas de /ws dans le chemin — l'ESP32-S3 écoute directement sur :81
  ws = new WebSocket(`ws://${ip}/ws`);

  ws.onopen = () => {
    setStatus(true);
    // Lance un ping toutes les 2 s pour mesurer la latence
    pingInterval = setInterval(sendPing, 2000);
  };

  ws.onclose = () => {
    setStatus(false);
    clearInterval(pingInterval);
    clearInterval(sendInterval);   // Arrête l'envoi répété des commandes
  };

  ws.onmessage = (e) => {
    try {
      const d = JSON.parse(e.data);

      // Réponse au ping → calcul latence aller-retour
      if (d.type === 'pong') {
        document.getElementById('latency').textContent =
          (Date.now() - pingTime) + ' ms';
        return;
      }
      // Données MQ-9 → mise à jour de l'affichage capteur
      if (d.type === 'sensor') updateSensors(d);
    } catch(_) {}
  };
}
Deux connexions indépendantes
Le dashboard v2 gère deux connexions séparées : le WebSocket :81 vers l'ESP32-S3 pour les commandes et les données MQ-9, et un flux MJPEG HTTP vers l'ESP32-CAM pour la vidéo. Les deux peuvent être connectées ou déconnectées indépendamment.

Mesure de latence

sendPing()
WebSocket

Envoie un {"type":"ping"} toutes les 2 secondes. L'ESP32 répond immédiatement avec {"type":"pong"}. La différence entre l'horodatage d'envoi et de réception donne la latence aller-retour en millisecondes, affichée dans la barre de statut.

JavaScriptsendPing() — mesure aller-retour
function sendPing() {
  if (ws?.readyState === 1) {   // 1 = OPEN
    pingTime = Date.now();
    ws.send(JSON.stringify({ type: 'ping' }));
  }
}
// La réponse est traitée dans ws.onmessage :
// if (d.type === 'pong') → latency = Date.now() - pingTime

Envoi d'une commande moteur

sendCmd(cmd)
WebSocket

Sérialise et envoie une commande JSON à l'ESP32. La vitesse est lue depuis le slider du dashboard et incluse dans chaque message. L'ESP32 utilise cette valeur pour calculer la durée de chaque phase de marche via moveMs().

JavaScriptsendCmd() — message JSON vers l'ESP32
function sendCmd(cmd) {
  if (ws?.readyState !== 1) { log('Non connecté', 'warn'); return; }

  const speed = parseInt(document.getElementById('speed').value);

  // Message envoyé : {"type":"cmd","cmd":"forward","speed":50}
  // L'ESP32 décode ce JSON dans onWsEvent() et met à jour pendingCmd + speedPct
  ws.send(JSON.stringify({ type: 'cmd', cmd, speed }));
  log(`> CMD ${cmd.toUpperCase()} speed=${speed}`, 'cmd');
}
CommandeEffet sur l'ESP32
forwardwalkForward() — trot diagonal vers l'avant
backwardwalkBackward() — trot diagonal vers l'arrière
leftCMD_LEFT — réservé (non implémenté dans ce firmware)
rightCMD_RIGHT — réservé
stopstandStill() — retour home

Gestion des boutons D-pad

startCmd(cmd, el) & stopCmd()
WSUI

startCmd() est déclenché au mousedown ou touchstart sur un bouton. Elle lance un setInterval qui renvoie la commande toutes les 150 ms — nécessaire car l'ESP32 est bloqué dans waitMove() pendant une phase et peut manquer un message unique. stopCmd() est déclenché au mouseup et envoie stop.

JavaScriptstartCmd() / stopCmd() — maintien de la commande
function startCmd(cmd, el) {
  if (currentCmd === cmd) return;   // Déjà en cours → ignore
  stopCmd();
  currentCmd = cmd;
  el.classList.add('pressed');    // Effet visuel bouton enfoncé
  setOsdCmd(cmd);                  // Affiche la commande en OSD sur la vidéo
  sendCmd(cmd);                    // Premier envoi immédiat

  // Ré-envoie toutes les 150 ms tant que le bouton est tenu
  // Permet à l'ESP32 de recevoir la commande même s'il était occupé
  if (cmd !== 'stop')
    sendInterval = setInterval(() => sendCmd(cmd), 150);
}

function stopCmd() {
  if (!currentCmd || currentCmd === 'stop') return;
  clearInterval(sendInterval);
  document.querySelectorAll('.btn').forEach(b => b.classList.remove('pressed'));
  setOsdCmd(null);
  currentCmd = null;
  sendCmd('stop');
}
Pourquoi réémettre toutes les 150 ms ?
L'ESP32-S3 est bloqué dans waitMove() pendant 300–800 ms par phase. Si le dashboard envoie un seul message forward, l'ESP peut le recevoir pendant une phase et le traiter, mais au cycle suivant il revient à CMD_STOP. Le réenvoi toutes les 150 ms garantit que pendingCmd reste à jour à chaque cycle.

Contrôle au clavier

keydown / keyup
UIWS

Les flèches du clavier déclenchent les mêmes fonctions startCmd()/stopCmd() que les boutons D-pad. La barre espace envoie stop.

JavaScriptMapping clavier → commandes
const KEY_CMD = {
  ArrowUp:    'forward',
  ArrowDown:  'backward',
  ArrowLeft:  'left',
  ArrowRight: 'right',
  ' ':        'stop'
};

document.addEventListener('keydown', e => {
  const cmd = KEY_CMD[e.key];
  if (!cmd) return;
  e.preventDefault();   // Empêche le scroll de la page
  const btn = document.querySelector(`.btn[data-cmd="${cmd}"]`);
  if (btn) startCmd(cmd, btn);
});

document.addEventListener('keyup', e => {
  const cmd = KEY_CMD[e.key];
  if (cmd && cmd !== 'stop') stopCmd();
});

Flux vidéo caméra

connectCam()
UI

Lance le flux MJPEG depuis l'ESP32-CAM. Le MJPEG (Motion JPEG) est un format vidéo où chaque frame est un JPEG indépendant envoyé en continu sur une connexion HTTP — le navigateur l'affiche nativement dans une balise <img>. La connexion de contrôle (pour changer résolution, qualité, flash) utilise des requêtes HTTP vers /control?var=...&val=... sur le port 80.

JavaScriptconnectCam() — stream MJPEG + fetch status
function connectCam() {
  const raw = document.getElementById('cam-ip').value.trim();

  // Sépare host:port si fourni, sinon port 81 par défaut pour le stream
  const [host, streamPort] = raw.includes(':')
    ? raw.split(':')
    : [raw, '81'];

  camBaseUrl = `http://${host}`;                         // port 80 : /control, /status
  const streamUrl = `http://${host}:${streamPort}/stream`;  // flux MJPEG

  fetchCamStatus(camBaseUrl);   // Récupère résolution, qualité…

  const img = document.getElementById('cam-img');
  let firstFrame = true;

  img.onload = () => {
    if (firstFrame) {
      firstFrame = false;
      setCamState('streaming');   // Premier frame reçu → état "EN DIRECT"
      startFpsCounter();
    }
    fpsCount++;   // Chaque onload = 1 frame → compteur FPS
  };

  img.onerror = () => setCamState('error');
  img.src = streamUrl;   // Déclenche le stream MJPEG
  camStreaming = true;
}
MJPEG dans une balise img
Assigner une URL MJPEG à img.src suffit : le navigateur maintient la connexion HTTP ouverte et décode chaque JPEG entrant comme une nouvelle frame. L'événement onload se déclenche à chaque frame, ce qui permet de compter les FPS. Aucune librairie vidéo n'est nécessaire.

Contrôle de la caméra

stopCam() & camControl(variable, value)
UI

stopCam() coupe le flux en vidant img.src. camControl() envoie des commandes HTTP GET à l'endpoint /control de l'ESP32-CAM pour modifier résolution, qualité JPEG, flip vertical, miroir horizontal, et flash LED.

JavaScriptcamControl() — requête HTTP /control
function camControl(variable, value) {
  if (!camBaseUrl) { log('CAM non connectée', 'warn'); return; }

  // Ex: http://192.168.1.50/control?var=framesize&val=8
  // Variables disponibles : framesize, quality, vflip, hmirror, flash…
  const url = `${camBaseUrl}/control?var=${variable}&val=${value}`;
  fetch(url).catch(() => log(`CAM contrôle échoué : ${variable}`, 'err'));
}

// Toggle flash LED
function toggleFlash() {
  camFlashOn = !camFlashOn;
  camControl('flash', camFlashOn ? 1 : 0);
}

Compteur FPS

startFpsCounter() / stopFpsCounter()
UI

Compte le nombre de frames reçues par seconde. Chaque onload de l'image MJPEG incrémente fpsCount. Un setInterval toutes les secondes affiche et remet à zéro ce compteur.

JavaScriptstartFpsCounter() — comptage frames MJPEG
function startFpsCounter() {
  stopFpsCounter();
  fpsCount = 0;
  fpsTimer = setInterval(() => {
    document.getElementById('info-fps').textContent = fpsCount;
    fpsCount = 0;   // Remet à zéro pour la prochaine seconde
  }, 1000);
}
// fpsCount++ à chaque img.onload dans connectCam()

Réception des données MQ-9

updateSensors(d)
ESP32 → navigateurUI

Appelée depuis ws.onmessage quand l'ESP32 envoie un message {"type":"sensor",...} toutes les 2 secondes. Met à jour l'affichage ppm, la barre de progression, et le badge d'alerte avec code couleur (normal / warn / danger).

JavaScriptupdateSensors() — affichage MQ-9 avec seuils
function updateSensors(d) {
  const ppmEl = document.getElementById('ppm');
  const ppm   = parseFloat(d.ppm) || 0;

  document.getElementById('raw').textContent     = d.raw ?? '—';
  document.getElementById('voltage').textContent =
    d.voltage ? parseFloat(d.voltage).toFixed(2) : '—';
  ppmEl.textContent = ppm.toFixed(1);

  // Barre de progression — MAX_PPM = 1000 ppm
  const pct = Math.min(ppm / MAX_PPM * 100, 100);
  document.getElementById('ppm-bar').style.width = pct + '%';

  // Couleur selon seuils : normal → warn (200 ppm) → danger (500 ppm)
  if      (ppm >= DANGER_PPM) ppmEl.className = 'metric-val danger'; // rouge clignotant
  else if (ppm >= WARN_PPM)   ppmEl.className = 'metric-val warn';   // orange
  else                        ppmEl.className = 'metric-val';          // cyan normal

  // Badge d'alerte digitale (sortie comparateur du module MQ-9)
  const badge = document.getElementById('alert-badge');
  if (d.alert) {
    badge.className = 'alert-badge danger';
    document.getElementById('alert-text').textContent = 'ALERTE GAZ';
  } else {
    badge.className = 'alert-badge';
    document.getElementById('alert-text').textContent = 'NORMAL';
  }
}

OSD sur la vidéo

setOsdCmd(cmd)
UI

Affiche la commande en cours (FORWARD, BACKWARD…) en surimpression sur le flux vidéo. L'OSD (On-Screen Display) est superposé au flux MJPEG via CSS position:absolute dans le viewport caméra.

JavaScriptsetOsdCmd() — surimpression sur la vidéo
function setOsdCmd(cmd) {
  const el = document.getElementById('osd-cmd');
  if (!cmd || cmd === 'stop') {
    el.textContent = 'EN ATTENTE';
  } else {
    el.textContent = cmd.toUpperCase();
  }
}

Journal des événements

log(msg, cls)
UI

Ajoute une ligne horodatée dans le panneau journal. Les classes CSS cmd, err, warn, cam colorent les entrées selon leur type. Le journal est limité à 40 entrées : les plus anciennes sont supprimées automatiquement.

JavaScriptlog() — journal horodaté, 40 entrées max
function log(msg, cls = 'entry') {
  const el  = document.getElementById('log');
  const now = new Date().toLocaleTimeString('fr-FR');
  el.innerHTML += `<div class="entry ${cls}">[${now}] ${msg}</div>`;
  el.scrollTop  = el.scrollHeight;
  while (el.children.length > 40) el.removeChild(el.firstChild);
}
// Classes : 'entry' (blanc), 'cmd' (cyan), 'err' (rouge), 'warn' (orange), 'cam' (orange2)
