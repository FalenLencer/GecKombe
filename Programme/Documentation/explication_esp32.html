Architecture du firmware

WSPCAMQ9

Le firmware tourne sur un seul cœur de l'ESP32. La boucle principale gère le réseau en permanence, mais les fonctions de marche sont bloquantes : pendant qu'un membre se déplace (via moveServo()), le CPU est occupé à calculer et envoyer les positions interpolées. Chaque appel à moveServo() appelle wsServer.loop() et httpServer.handleClient() entre chaque micro-pas pour garder la connexion WebSocket vivante.

┌──────────────────── loop() ─────────────────────────────────────────────┐ │ │ │ httpServer.handleClient() ←── requêtes HTTP port 80 │ │ wsServer.loop() ←── messages WebSocket → onWsEvent() │ │ │ │ │ met à jour currentCmd / speed │ │ │ │ switch(currentCmd) │ │ CMD_FORWARD → walkForward() ←── bloquant : plusieurs delay() │ │ CMD_BACKWARD → walkBackward() │ │ CMD_LEFT → walkLeft() │ │ CMD_RIGHT → walkRight() │ │ CMD_STOP → standStill() (une seule fois via wasMoving) │ │ │ │ chaque walkXxx() appelle liftMember() x4 │ │ └─► moveServo() ──► ease-in-out ──► PCA9685 (I2C) ──► servo │ │ └── delay(MS_PER_STEP) + wsServer.loop() à chaque micro-pas │ │ │ │ toutes les 2 s : readMQ9() ──► JSON ──► broadcastTXT() │ └──────────────────────────────────────────────────────────────────────────┘

Constantes & variables d'état

PCAMQ9

Toutes les constantes de calibration sont regroupées en tête de fichier pour faciliter le réglage sans toucher à la logique.

C++Constantes de mouvement et limites mécaniques
// ── Canaux PCA9685 ────────────────────────────────────────────────────────
// Chaque membre a 2 servos : hanche (hip) et genou (knee)
// Les indices correspondent aux sorties LED00 à LED07 du PCA9685
#define SERVO_BR_HIP    0   // Postérieur Droit  — hanche
#define SERVO_BR_KNEE   1   // Postérieur Droit  — genou
#define SERVO_BL_HIP    2   // Postérieur Gauche — hanche
#define SERVO_BL_KNEE   3   // Postérieur Gauche — genou
#define SERVO_FR_HIP    4   // Antérieur Droit   — hanche
#define SERVO_FR_KNEE   5   // Antérieur Droit   — genou
#define SERVO_FL_HIP    6   // Antérieur Gauche  — hanche
#define SERVO_FL_KNEE   7   // Antérieur Gauche  — genou

// ── Limites mécaniques (ticks PCA9685 à 50 Hz) ───────────────────────────
// Les hanches et les genoux ont des plages différentes pour protéger
// la mécanique : un genou ne va pas jusqu'à 0° ni jusqu'à 180°
#define HIP_MIN   150   // Hanche → ~0°
#define HIP_MID   375   // Hanche → ~90° (position neutre)
#define HIP_MAX   600   // Hanche → ~180°
#define KNEE_MIN  263   // Genou  → ~45°
#define KNEE_MID  375   // Genou  → ~90° (position neutre)
#define KNEE_MAX  487   // Genou  → ~135°

// ── Paramètres d'interpolation ────────────────────────────────────────────
// INTERP_STEPS : nombre de micro-pas entre deux positions
//   Plus c'est grand = plus le mouvement est fluide (mais plus lent)
// MS_PER_STEP : durée fixe d'un micro-pas en millisecondes
//   Minimum 30 ms pour que le servo atteigne physiquement la position cible
#define INTERP_STEPS   20
#define MS_PER_STEP    30

// ── Amplitudes de mouvement ───────────────────────────────────────────────
// HIP_AMPLITUDE : débattement de la hanche de chaque côté du centre (±70 ticks)
// KNEE_LIFT     : descente du genou pour lever le pied (KNEE_MID - 100)
#define HIP_AMPLITUDE  70
#define KNEE_LIFT      100
C++Variables d'état globales
// Commande en cours — mise à jour par onWsEvent(), lue par loop()
enum Command { CMD_STOP, CMD_FORWARD, CMD_BACKWARD, CMD_LEFT, CMD_RIGHT };
volatile Command currentCmd = CMD_STOP;

// Vitesse 0–100 reçue du dashboard (non utilisée pour varier la vitesse
// dans cette version : la vitesse est fixée par MS_PER_STEP et INTERP_STEPS)
volatile uint8_t speed = 50;

// Permet d'appeler standStill() UNE SEULE FOIS à l'arrêt,
// et non à chaque tour de loop() quand le robot est immobile
bool wasMoving = false;

// Horodatage du dernier envoi MQ-9 (pour le timer toutes les 2 s)
uint32_t lastSensorSend = 0;

// Positions courantes de chaque servo — mémorisées pour que moveServo()
// puisse interpoler depuis la vraie position actuelle et non depuis zéro
uint16_t curPos[8];
Pourquoi volatile ?
currentCmd et speed sont déclarées volatile car elles sont modifiées depuis le handler WebSocket (onWsEvent()) et lues depuis la boucle principale — le compilateur ne doit pas les mettre en cache dans un registre.

Initialisation — setup()

WSPCANET

Exécutée une seule fois au démarrage. Elle initialise dans l'ordre : les pins GPIO, le bus I2C et le PCA9685, les positions courantes de tous les servos, la connexion WiFi, puis les deux serveurs réseau.

C++setup() — séquence d'initialisation complète
void setup() {
  Serial.begin(115200);

  // ── 1. Pins MQ-9 ─────────────────────────────────────────────────────
  // GPIO34 = entrée analogique ADC (ADC1 — compatible WiFi actif)
  // GPIO32 = entrée digitale (seuil réglable via potentiomètre du module)
  pinMode(MQ9_ANALOG_PIN,  INPUT);   // GPIO34
  pinMode(MQ9_DIGITAL_PIN, INPUT);   // GPIO32

  // ── 2. PCA9685 via I2C (SDA=GPIO21, SCL=GPIO22) ─────────────────────
  // Adresse I2C 0x40 = adresse par défaut (toutes cavalières ouvertes)
  // setPWMFreq(50) = fréquence standard des servos (période 20 ms)
  Wire.begin(21, 22);
  pca.begin();
  pca.setPWMFreq(50);
  delay(500);  // Laisse le temps aux servos de s'initialiser

  // ── 3. Initialisation de curPos[] ────────────────────────────────────
  // Les hanches (index pairs) partent au centre (HIP_MID = 375)
  // Les genoux  (index impairs) partent au centre (KNEE_MID = 375)
  // Cela permet à moveServo() d'interpoler correctement dès le premier appel
  for (int i = 0; i < 8; i++)
    curPos[i] = (i % 2 == 0) ? HIP_MID : KNEE_MID;

  // Envoie directement les positions neutres au PCA9685 (sans interpolation)
  for (int i = 0; i < 8; i++)
    pca.setPWM(i, 0, curPos[i]);
  delay(500);

  // ── 4. Connexion WiFi ─────────────────────────────────────────────────
  WiFi.begin(SSID, PASSWORD);
  while (WiFi.status() != WL_CONNECTED) { delay(500); Serial.print("."); }
  Serial.printf("\nConnecté — IP : http://%s\n", WiFi.localIP().toString().c_str());
  Serial.printf("WebSocket  : ws://%s:81/ws\n", WiFi.localIP().toString().c_str());

  // ── 5. Serveur HTTP port 80 et WebSocket port 81 ─────────────────────
  httpServer.on("/", handleRoot);
  httpServer.begin();
  wsServer.begin();
  wsServer.onEvent(onWsEvent);
}
Pourquoi initialiser curPos[] avant d'envoyer les servos ?
moveServo() part de curPos[ch] pour calculer l'interpolation. Si ce tableau contient des valeurs arbitraires (zéro ou aléatoires), le premier mouvement partirait d'une position fausse et pourrait forcer mécaniquement le servo. L'initialisation à HIP_MID/KNEE_MID garantit que la première interpolation est cohérente avec la position physique réelle.

Boucle principale — loop()

WSPCAMQ9

Tourne en permanence après setup(). Elle commence par pomper le réseau (handleClient + wsServer.loop()), puis exécute la marche via un switch sur currentCmd. Les fonctions de marche sont bloquantes : elles s'exécutent entièrement avant que loop() reprenne. L'envoi MQ-9 toutes les 2 secondes est géré par un timer millis() non-bloquant, mais il n'est atteint que quand le robot est à l'arrêt (en CMD_STOP).

C++loop() — switch sur currentCmd
void loop() {
  // Pompage réseau — traite les paquets HTTP et WebSocket en attente
  httpServer.handleClient();
  wsServer.loop();

  switch (currentCmd) {

    case CMD_FORWARD:
      wasMoving = true;
      walkForward();   // bloquant — dure plusieurs secondes
      break;

    case CMD_BACKWARD:
      wasMoving = true;
      walkBackward();
      break;

    case CMD_LEFT:
      wasMoving = true;
      walkLeft();
      break;

    case CMD_RIGHT:
      wasMoving = true;
      walkRight();
      break;

    case CMD_STOP:
    default:
      // standStill() une seule fois à l'arrêt grâce à wasMoving
      // Sans ce garde-fou, standStill() serait appelée à chaque tour
      // de loop() et enverrait inutilement 8 commandes I2C en boucle
      if (wasMoving) {
        wasMoving = false;
        standStill();
      }
      // Pendant l'arrêt : pompe le réseau et envoie les données capteur
      httpServer.handleClient();
      wsServer.loop();
      break;
  }

  // ── Envoi MQ-9 toutes les 2 secondes ─────────────────────────────────
  // Ce bloc n'est atteint régulièrement qu'à l'arrêt (CMD_STOP),
  // car pendant la marche loop() est bloqué dans walkXxx()
  if (millis() - lastSensorSend > 2000) {
    lastSensorSend = millis();
    SensorData d = readMQ9();

    StaticJsonDocument<160> doc;
    doc["type"]    = "sensor";
    doc["raw"]     = d.raw;
    doc["voltage"] = serialized(String(d.voltage, 3));
    doc["rs"]      = serialized(String(d.rs,      3));
    doc["ratio"]   = serialized(String(d.ratio,   3));
    doc["ppm"]     = serialized(String(d.ppm,     1));
    doc["alert"]   = d.alert;

    String out;
    serializeJson(doc, out);
    wsServer.broadcastTXT(out);
  }
}
Les fonctions de marche sont bloquantes
Contrairement à une architecture non-bloquante basée sur millis(), les fonctions walkXxx() contiennent des delay() à l'intérieur de moveServo(). Pendant ces délais, loop() ne reprend pas. C'est pourquoi moveServo() appelle manuellement wsServer.loop() et httpServer.handleClient() à chaque micro-pas pour éviter que la connexion WebSocket ne timeout.

Réception des commandes — onWsEvent()

WebSocket entrant

Callback appelé automatiquement par la librairie WebSocketsServer à chaque événement réseau. Elle décode le JSON entrant et met à jour currentCmd et speed. À la déconnexion d'un client, elle force currentCmd = CMD_STOP par sécurité.

C++onWsEvent() — parsing JSON et routage des commandes
void onWsEvent(uint8_t num, WStype_t type,
               uint8_t* payload, size_t length) {

  if (type == WStype_TEXT) {
    StaticJsonDocument<128> doc;
    if (deserializeJson(doc, payload, length)) return;

    const char* t = doc["type"];
    if (!t) return;

    // ── Ping de latence ───────────────────────────────────────────────────
    // Le dashboard envoie {"type":"ping"} toutes les 2 s pour mesurer la latence
    // L'ESP répond immédiatement {"type":"pong"} sans rien d'autre
    if (strcmp(t, "ping") == 0) {
      wsServer.sendTXT(num, "{\"type\":\"pong\"}");
      return;
    }

    // ── Commande de déplacement ───────────────────────────────────────────
    // Le dashboard envoie {"type":"cmd","cmd":"forward","speed":50}
    if (strcmp(t, "cmd") == 0) {
      const char* cmd = doc["cmd"];

      // Extrait la vitesse, défaut 50 si absente (opérateur | = valeur par défaut)
      speed = constrain((int)doc["speed"] | 50, 0, 100);

      if      (strcmp(cmd, "forward")  == 0) currentCmd = CMD_FORWARD;
      else if (strcmp(cmd, "backward") == 0) currentCmd = CMD_BACKWARD;
      else if (strcmp(cmd, "left")     == 0) currentCmd = CMD_LEFT;
      else if (strcmp(cmd, "right")    == 0) currentCmd = CMD_RIGHT;
      else                                    currentCmd = CMD_STOP;
    }
  }

  // ── Déconnexion ───────────────────────────────────────────────────────
  // Immobilise le robot si le navigateur est fermé ou si le WiFi coupe
  // Note : standStill() n'est PAS appelée ici — wasMoving déclenchera
  // l'arrêt propre au prochain tour de loop()
  if (type == WStype_DISCONNECTED) {
    currentCmd = CMD_STOP;
  }
}
Sécurité — déconnexion
Si le WiFi coupe ou si le navigateur est fermé, WStype_DISCONNECTED est déclenché et currentCmd passe à CMD_STOP. La fonction de marche en cours détecte ce changement (via if (currentCmd != CMD_FORWARD) return;) et s'interrompt, puis loop() appellera standStill() via wasMoving.

Envoi direct — rawPWM()

PCA9685 PWM

Envoie une commande PWM immédiatement au PCA9685, sans interpolation. Utilisée quand la fluidité n'est pas requise : repositionnement rapide des hanches au centre, initialisation au démarrage.

C++rawPWM() — envoi direct, borne selon le type de servo
void rawPWM(uint8_t ch, uint16_t t, bool isKnee) {
  // Borne la valeur selon les limites de la hanche ou du genou
  // Protège mécaniquement le servo contre les dépassements
  t = isKnee ? constrain(t, KNEE_MIN, KNEE_MAX)
             : constrain(t, HIP_MIN,  HIP_MAX);

  // Met à jour curPos pour que moveServo() parte du bon point lors
  // du prochain mouvement interpolé
  curPos[ch] = t;
  pca.setPWM(ch, 0, t);
}

Interpolation fluide — moveServo()

PCA9685 PWM

C'est le moteur de fluidité du firmware. Elle déplace un servo de sa position actuelle vers une cible en INTERP_STEPS micro-pas, avec une courbe ease-in-out cubique : le mouvement commence lentement, accélère au milieu, puis ralentit à l'arrivée — exactement comme un mouvement naturel.

C++moveServo() — interpolation ease-in-out cubique
void moveServo(uint8_t ch, uint16_t target, bool isKnee) {
  // Borne la cible dans les limites mécaniques
  target = isKnee ? constrain(target, KNEE_MIN, KNEE_MAX)
                  : constrain(target, HIP_MIN,  HIP_MAX);

  int32_t start = curPos[ch];          // Position de départ = position courante mémorisée
  int32_t delta = (int32_t)target - start;
  if (delta == 0) return;             // Déjà en position → rien à faire

  for (int s = 1; s <= INTERP_STEPS; s++) {

    // ── Ease-in-out cubique ───────────────────────────────────────────────
    // t va de 0.0 à 1.0 sur toute la durée du mouvement
    // Formule : t < 0.5 → 4t³   |   t ≥ 0.5 → 1 - (-2t+2)³/2
    // Résultat : courbe en S — lent au départ, rapide au milieu, lent à l'arrivée
    float t    = (float)s / INTERP_STEPS;
    float ease = t < 0.5f ? 4*t*t*t : 1 - pow(-2*t+2, 3)/2;

    uint16_t pos = (uint16_t)(start + delta * ease);
    curPos[ch] = pos;
    pca.setPWM(ch, 0, pos);

    // Pause fixe entre chaque micro-pas
    // 30 ms = durée minimale pour que le servo atteigne physiquement la position
    delay(MS_PER_STEP);

    // Pompe le réseau pendant le délai pour garder le WebSocket vivant
    // Sans ces appels, la connexion timeouterait pendant la marche
    wsServer.loop();
    httpServer.handleClient();
  }

  // Force la position exacte à la fin (évite les erreurs d'arrondi float)
  curPos[ch] = target;
  pca.setPWM(ch, 0, target);
}
La courbe ease-in-out cubique
Avec INTERP_STEPS = 20 et MS_PER_STEP = 30 ms, un mouvement complet dure 20 × 30 = 600 ms. Augmenter INTERP_STEPS rend le mouvement plus fluide mais plus lent. Augmenter MS_PER_STEP donne plus de temps au servo pour atteindre chaque position intermédiaire — utile si le servo est lent ou chargé.

Lever d'un membre — liftMember()

PCA9685

Réalise le lever complet d'un membre en 3 phases séquentielles, imitant la démarche naturelle d'un cheval : décoller, avancer, poser. Chaque phase fait appel à moveServo() et est suivie d'une courte pause pour laisser les servos terminer leur mouvement.

C++liftMember() — 3 phases : lever, avancer, poser
void liftMember(uint8_t hipCh, uint8_t kneeCh, uint16_t hipTarget) {
  // Position genou levé : KNEE_MID - KNEE_LIFT (= 375 - 100 = 275 ticks)
  // constrain() s'assure que ça reste dans la plage autorisée [KNEE_MIN, KNEE_MAX]
  uint16_t kneeUp = constrain(KNEE_MID - KNEE_LIFT, KNEE_MIN, KNEE_MAX);

  // Phase 1 : le genou se lève → le pied décolle du sol
  moveServo(kneeCh, kneeUp,    true);
  delay(20);

  // Phase 2 : la hanche avance vers la cible → le pied avance en l'air
  moveServo(hipCh,  hipTarget, false);
  delay(20);

  // Phase 3 : le genou se repose → le pied touche le sol en avant
  moveServo(kneeCh, KNEE_MID,  true);
  delay(20);
}
Séquence liftMember() — vue de profil d'un membre Phase 1 : genou lève Phase 2 : hanche avance Phase 3 : genou pose ┌──────────────┐ ┌──────────────┐ ┌──────────────┐ │ corps │ │ corps │ │ corps │ │ │ │ │ │ │ │ │ │ │ hanche │ │ hanche ──► │ │ hanche │ │ │ │ │ │ │ │ │ │ │ genou ─► │ │ genou ─► │ │ genou │ │ \ │ │ \ │ │ │ │ │ pied ↑ │ │ pied ↑ │ │ pied ▼ │ └──────────────┘ └──────────────┘ └──────────────┘ pied décolle pied avance en l'air pied touche le sol

Recentrage des hanches — centerAllHips()

PCA9685

Recentre toutes les hanches à HIP_MID en même temps, sans interpolation (via rawPWM), puis attend suffisamment pour qu'elles atteignent physiquement le centre. Appelée à la fin de chaque cycle de marche complet pour remettre le robot en position neutre avant le cycle suivant.

C++centerAllHips() — recentrage simultané des 4 hanches
void centerAllHips() {
  // Envoi direct (rawPWM) car les hanches sont déjà proches du centre
  // après un cycle — l'interpolation serait inutilement lente ici
  rawPWM(SERVO_BR_HIP, HIP_MID, false);
  rawPWM(SERVO_BL_HIP, HIP_MID, false);
  rawPWM(SERVO_FR_HIP, HIP_MID, false);
  rawPWM(SERVO_FL_HIP, HIP_MID, false);

  // Délai pour laisser les 4 servos atteindre physiquement le centre
  // MS_PER_STEP * 4 = 120 ms
  delay(MS_PER_STEP * 4);
}

Posture neutre — standStill()

PCA9685

Place tous les servos (hanches et genoux) en position neutre KNEE_MID/HIP_MID via des appels interpolés à moveServo(), puis recentre les hanches. Appelée une seule fois à l'arrêt (via wasMoving), au démarrage et à la déconnexion du client.

C++standStill() — posture neutre interpolée
void standStill() {
  // Ramène les 4 genoux au centre avec interpolation ease-in-out
  // → transition douce sans à-coups, quel que soit leur position actuelle
  moveServo(SERVO_BR_KNEE, KNEE_MID, true);
  moveServo(SERVO_BL_KNEE, KNEE_MID, true);
  moveServo(SERVO_FR_KNEE, KNEE_MID, true);
  moveServo(SERVO_FL_KNEE, KNEE_MID, true);

  // Puis recentre toutes les hanches en même temps (sans interpolation)
  centerAllHips();
}

Marche avant — walkForward()

PCA9685

Exécute un cycle complet de marche vers l'avant. L'ordre de déplacement des membres imite la démarche du cheval : PD → AG → PG → AD (deux membres diagonaux opposés bougent séquentiellement). Après chaque membre, la fonction vérifie si la commande a changé — si oui, elle s'arrête immédiatement pour réagir rapidement aux ordres du dashboard.

C++walkForward() — ordre de marche cheval PD→AG→PG→AD
void walkForward() {
  // Position avant = HIP_MID + HIP_AMPLITUDE  (= 375 + 70 = 445 ticks)
  // Position arrière = HIP_MID - HIP_AMPLITUDE (= 375 - 70 = 305 ticks)
  // Les membres gauches ont les directions inversées pour avancer tous dans le même sens
  uint16_t fwd = HIP_MID + HIP_AMPLITUDE;  // 445
  uint16_t bwd = HIP_MID - HIP_AMPLITUDE;  // 305

  liftMember(SERVO_BR_HIP, SERVO_BR_KNEE, fwd);  // PD avance → sens "fwd"
  if (currentCmd != CMD_FORWARD) return;           // Arrêt immédiat si commande changée

  liftMember(SERVO_FL_HIP, SERVO_FL_KNEE, bwd);  // AG avance → sens inversé "bwd"
  if (currentCmd != CMD_FORWARD) return;

  liftMember(SERVO_BL_HIP, SERVO_BL_KNEE, fwd);  // PG avance → sens "fwd"
  if (currentCmd != CMD_FORWARD) return;

  liftMember(SERVO_FR_HIP, SERVO_FR_KNEE, bwd);  // AD avance → sens inversé "bwd"
  if (currentCmd != CMD_FORWARD) return;

  centerAllHips();  // Recentre pour repartir proprement au prochain cycle
}
Pourquoi les membres gauches ont "bwd" pour avancer ?
Les servos droits et gauches sont montés en miroir l'un de l'autre. Pour que tous les membres avancent dans la même direction (vers l'avant du robot), les hanches gauches doivent tourner dans le sens opposé aux hanches droites.

Marche arrière — walkBackward()

PCA9685

Même ordre de membres que walkForward(), mais les cibles de hanche sont inversées : ce qui était fwd devient bwd et vice-versa.

C++walkBackward() — directions hanches inversées
void walkBackward() {
  uint16_t fwd = HIP_MID + HIP_AMPLITUDE;
  uint16_t bwd = HIP_MID - HIP_AMPLITUDE;

  // Directions inversées par rapport à walkForward() → recule
  liftMember(SERVO_BR_HIP, SERVO_BR_KNEE, bwd);
  if (currentCmd != CMD_BACKWARD) return;

  liftMember(SERVO_FL_HIP, SERVO_FL_KNEE, fwd);
  if (currentCmd != CMD_BACKWARD) return;

  liftMember(SERVO_BL_HIP, SERVO_BL_KNEE, bwd);
  if (currentCmd != CMD_BACKWARD) return;

  liftMember(SERVO_FR_HIP, SERVO_FR_KNEE, fwd);
  if (currentCmd != CMD_BACKWARD) return;

  centerAllHips();
}

Virages — walkLeft() / walkRight()

PCA9685

Les virages utilisent une différence d'amplitude entre les membres d'un côté et de l'autre : le côté qui avance fort fait pivoter le robot. Les membres droits avancent de HIP_AMPLITUDE (fort) et les membres gauches de HIP_AMPLITUDE / 3 (faible) pour virer à gauche — et inversement pour virer à droite.

C++walkLeft() — membres droits avancent fort, gauches peu
void walkLeft() {
  uint16_t strongFwd = HIP_MID + HIP_AMPLITUDE;        // 445 — grand pas
  uint16_t weakFwd   = HIP_MID + HIP_AMPLITUDE / 3;    // 398 — petit pas
  uint16_t strongBwd = HIP_MID - HIP_AMPLITUDE;        // 305
  uint16_t weakBwd   = HIP_MID - HIP_AMPLITUDE / 3;    // 352

  liftMember(SERVO_BR_HIP, SERVO_BR_KNEE, strongFwd); // PD avance fort → pousse à gauche
  if (currentCmd != CMD_LEFT) return;

  liftMember(SERVO_FL_HIP, SERVO_FL_KNEE, weakBwd);   // AG avance peu
  if (currentCmd != CMD_LEFT) return;

  liftMember(SERVO_BL_HIP, SERVO_BL_KNEE, strongFwd); // PG avance fort → pousse à gauche
  if (currentCmd != CMD_LEFT) return;

  liftMember(SERVO_FR_HIP, SERVO_FR_KNEE, weakBwd);   // AD avance peu
  if (currentCmd != CMD_LEFT) return;

  centerAllHips();
}

void walkRight() {
  uint16_t strongFwd = HIP_MID + HIP_AMPLITUDE;
  uint16_t weakBwd   = HIP_MID - HIP_AMPLITUDE / 3;
  uint16_t strongBwd = HIP_MID - HIP_AMPLITUDE;
  uint16_t weakFwd   = HIP_MID + HIP_AMPLITUDE / 3;

  // Inverse des rôles par rapport à walkLeft() : membres gauches avancent fort
  liftMember(SERVO_BR_HIP, SERVO_BR_KNEE, weakFwd);
  if (currentCmd != CMD_RIGHT) return;

  liftMember(SERVO_FL_HIP, SERVO_FL_KNEE, strongBwd);
  if (currentCmd != CMD_RIGHT) return;

  liftMember(SERVO_BL_HIP, SERVO_BL_KNEE, weakFwd);
  if (currentCmd != CMD_RIGHT) return;

  liftMember(SERVO_FR_HIP, SERVO_FR_KNEE, strongBwd);
  if (currentCmd != CMD_RIGHT) return;

  centerAllHips();
}

Lecture du capteur gaz — readMQ9()

MQ-9 ADC

Lit les deux sorties du module MQ-9 et calcule une estimation en ppm de CO. Le calcul suit la courbe caractéristique de la datasheet du MQ-9, modélisée par une loi puissance log-log.

C++readMQ9() — lecture ADC et calcul ppm CO
SensorData readMQ9() {
  SensorData d;

  // ── Lecture analogique (GPIO34, ADC1) ─────────────────────────────────
  // analogRead() retourne 0–4095 (résolution 12 bits de l'ESP32)
  // GPIO34 est sur ADC1 → compatible avec le WiFi actif (ADC2 ne l'est pas)
  d.raw = analogRead(MQ9_ANALOG_PIN);

  // ── Lecture digitale (GPIO32) ─────────────────────────────────────────
  // LOW = le comparateur interne du module a détecté un dépassement de seuil
  // Le seuil est réglable via le potentiomètre bleu du module MQ-9
  d.alert = digitalRead(MQ9_DIGITAL_PIN) == LOW;

  // ── Conversion en volts (ADC 12 bits, 0–3.3 V) ───────────────────────
  d.voltage = (d.raw / ADC_MAX) * VCC;   // ADC_MAX=4095, VCC=3.3

  // ── Calcul de RS (résistance interne du capteur) ──────────────────────
  // Le module MQ-9 est un pont diviseur : VCC — RS — Vout — RL — GND
  // D'où : RS = RL × (VCC − Vout) / Vout
  // RL_VALUE = 10 kΩ (valeur typique sur les modules)
  d.rs = (d.voltage > 0.01f) ? RL_VALUE * (VCC - d.voltage) / d.voltage : 0;

  // ── Ratio RS/RO ───────────────────────────────────────────────────────
  // RO = résistance dans l'air pur (à calibrer, défaut = 10 kΩ)
  // Plus le ratio est faible, plus la concentration de gaz est élevée
  d.ratio = d.rs / RO;

  // ── Estimation CO en ppm (courbe datasheet MQ-9) ─────────────────────
  // La datasheet donne une droite log-log → ppm = a × (RS/RO)^b
  // Pour le CO : a=599.65, b=-2.244 (ajustés depuis la courbe graphique)
  d.ppm = (d.ratio > 0) ? 599.65f * pow(d.ratio, -2.244f) : 0;

  return d;
}
Calibration obligatoire — la valeur RO
La constante RO (résistance dans l'air pur) varie d'un capteur à l'autre. Pour calibrer : laisse le MQ-9 chauffer 5 minutes en air pur, relève la valeur de d.rs dans le moniteur série, et remplace RO = 10.0 par cette valeur mesurée. Sans calibration, les ppm sont indicatives seulement.
