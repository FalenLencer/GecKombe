Architecture du firmware

WSPCAMQ9

Le firmware tourne sur un seul cœur de l'ESP32 et gère trois tâches en parallèle dans la boucle principale : répondre aux clients WebSocket, avancer d'une frame de marche, et envoyer les données MQ-9 toutes les 2 secondes.

┌─────────────────── loop() — tourne en continu ───────────────────────┐ │ │ │ httpServer.handleClient() ←── répond aux requêtes HTTP port 80 │ │ wsServer.loop() ←── traite les messages WebSocket port 81 │ │ │ │ │ └──► onWsEvent() ←── parse JSON, met à jour currentCmd │ │ │ │ tickGait() ←── avance d'une frame si le délai est écoulé │ │ │ │ │ └──► applyFrame() ──► setServo() x8 ──► PCA9685 (I2C) │ │ │ │ │ 8 servo-moteurs │ │ │ │ toutes les 2 s : readMQ9() ──► JSON ──► wsServer.broadcastTXT() │ └───────────────────────────────────────────────────────────────────────┘

Les variables currentCmd et speed sont déclarées volatile car elles sont modifiées depuis le handler WebSocket et lues depuis la boucle principale — deux contextes d'exécution différents.

C++Variables d'état globales
// Commande en cours — mise à jour par onWsEvent(), lue par tickGait()
enum Command { CMD_STOP, CMD_FORWARD, CMD_BACKWARD, CMD_LEFT, CMD_RIGHT };
volatile Command currentCmd = CMD_STOP;

// Vitesse 0-100 reçue du dashboard
volatile uint8_t speed = 50;

// Index de la frame de marche en cours (avance à chaque tickGait)
uint8_t  gaitFrame      = 0;

// Timestamps pour les timers non-bloquants
uint32_t lastGaitStep   = 0;  // Dernière frame de marche
uint32_t lastSensorSend = 0;  // Dernier envoi MQ-9

Initialisation — setup()

WSPCANET

Exécutée une seule fois au démarrage. Elle initialise dans l'ordre : les pins GPIO, le PCA9685 via I2C, la connexion WiFi, puis les deux serveurs réseau.

C++setup() — séquence d'initialisation complète
void setup() {
  Serial.begin(115200);

  // ── 1. Pins MQ-9 ─────────────────────────────────────────────
  // GPIO34 = entrée analogique (ADC1, compatible WiFi)
  // GPIO32 = entrée digitale (seuil du comparateur interne)
  pinMode(MQ9_ANALOG_PIN,  INPUT);
  pinMode(MQ9_DIGITAL_PIN, INPUT);

  // ── 2. PCA9685 via I2C (SDA=GPIO21, SCL=GPIO22) ──────────────
  // Adresse I2C par défaut : 0x40 (toutes les cavalières ouvertes)
  Wire.begin();
  pca.begin();
  pca.setOscillatorFrequency(27000000); // Fréquence interne réelle du quartz
  pca.setPWMFreq(SERVO_FREQ);          // 50 Hz = fréquence standard servo
  delay(10);
  standStill();  // Place tous les servos en position neutre au démarrage

  // ── 3. Connexion WiFi ─────────────────────────────────────────
  WiFi.begin(SSID, PASSWORD);
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
  // Affiche l'IP à ouvrir dans le dashboard
  Serial.printf("\nIP : http://%s\n", WiFi.localIP().toString().c_str());

  // ── 4. Serveur HTTP port 80 (page de statut simple) ───────────
  httpServer.on("/", handleRoot);
  httpServer.begin();

  // ── 5. Serveur WebSocket port 81 ─────────────────────────────
  // onWsEvent est le callback appelé à chaque événement WebSocket
  wsServer.begin();
  wsServer.onEvent(onWsEvent);
}
Pourquoi setOscillatorFrequency(27000000) ?
Le PCA9685 possède un oscillateur interne censé fonctionner à 25 MHz, mais en pratique la plupart des modules chinois oscillent à ~27 MHz. Sans cette correction, la fréquence PWM réelle serait ~54 Hz au lieu de 50 Hz, et les servos recevraient des impulsions légèrement décalées — ce qui les ferait vibrer ou se positionner incorrectement.

Boucle principale — loop()

WSPCAMQ9

Tourne en permanence après setup(). Elle ne contient aucun delay() — tout est géré par des timers non-bloquants basés sur millis(). Cela permet de traiter les WebSocket et de faire avancer la marche simultanément sans qu'une tâche bloque l'autre.

C++loop() — trois tâches en parallèle sans blocage
void loop() {
  // ── Tâche 1 : réseau ─────────────────────────────────────────
  // handleClient() traite les requêtes HTTP en attente
  // wsServer.loop() traite les messages WebSocket et appelle onWsEvent()
  httpServer.handleClient();
  wsServer.loop();

  // ── Tâche 2 : marche ─────────────────────────────────────────
  // tickGait() vérifie en interne si le délai entre frames est écoulé
  // Si oui → avance d'une frame et pilote les servos
  // Si non → retour immédiat sans rien faire
  tickGait();

  // ── Tâche 3 : envoi capteur MQ-9 toutes les 2 secondes ────────
  if (millis() - lastSensorSend > 2000) {
    lastSensorSend = millis();

    SensorData d = readMQ9();

    // Construit le JSON et le diffuse à tous les clients connectés
    StaticJsonDocument<160> doc;
    doc["type"]    = "sensor";
    doc["raw"]     = d.raw;
    doc["voltage"] = serialized(String(d.voltage, 3));
    doc["ppm"]     = serialized(String(d.ppm,     1));
    doc["alert"]   = d.alert;

    String out;
    serializeJson(doc, out);
    wsServer.broadcastTXT(out);  // Envoi à tous les clients WebSocket
  }
}
Pourquoi pas de delay() ?
Un delay(100) bloquerait tout : pendant ces 100 ms, aucun paquet WebSocket ne serait traité, la marche serait hachée, et le dashboard verrait la connexion comme instable. La technique millis() permet de "vérifier" si le temps est écoulé sans jamais bloquer le processeur.

Réception des commandes — onWsEvent()

WebSocket entrant

C'est la fonction appelée automatiquement par la librairie WebSocketsServer à chaque événement réseau. Elle reçoit les messages JSON du dashboard, les décode, et met à jour currentCmd et speed — les deux variables que tickGait() lit pour savoir quoi faire.

C++onWsEvent() — parsing JSON et routage des commandes
void onWsEvent(uint8_t num, WStype_t type,
               uint8_t* payload, size_t length) {

  // L'événement WStype_TEXT signifie qu'un message texte a été reçu
  // (le dashboard envoie toujours du JSON texte)
  if (type == WStype_TEXT) {

    // Décode le JSON reçu dans un document de 128 octets max
    // StaticJsonDocument alloue sur la pile (pas de malloc)
    StaticJsonDocument<128> doc;
    if (deserializeJson(doc, payload, length)) return; // JSON invalide → ignore

    const char* t = doc["type"];
    if (!t) return;

    // ── Ping du dashboard → répondre immédiatement ────────────────
    // Le dashboard mesure Date.now() - pingTime pour calculer la latence
    if (strcmp(t, "ping") == 0) {
      wsServer.sendTXT(num, "{\"type\":\"pong\"}");
      return;
    }

    // ── Commande de déplacement ───────────────────────────────────
    if (strcmp(t, "cmd") == 0) {
      const char* cmd = doc["cmd"];

      // Extrait la vitesse (0-100), valeur par défaut 50 si absente
      speed = constrain((int)doc["speed"] | 50, 0, 100);

      // Met à jour currentCmd — tickGait() la lira au prochain cycle
      if      (strcmp(cmd, "forward")  == 0) currentCmd = CMD_FORWARD;
      else if (strcmp(cmd, "backward") == 0) currentCmd = CMD_BACKWARD;
      else if (strcmp(cmd, "left")     == 0) currentCmd = CMD_LEFT;
      else if (strcmp(cmd, "right")    == 0) currentCmd = CMD_RIGHT;
      else                                    currentCmd = CMD_STOP;

      gaitFrame = 0; // Repart du début de la séquence à chaque nouvelle commande
    }
  }

  // Déconnexion d'un client → sécurité : immobiliser le robot
  if (type == WStype_DISCONNECTED) {
    currentCmd = CMD_STOP;
    standStill(); // Servobrakes en position neutre immédiatement
  }
}

Le paramètre num est l'identifiant du client WebSocket. Un même ESP32 peut gérer plusieurs clients connectés simultanément — sendTXT(num, ...) répond uniquement au client qui a envoyé le message, tandis que broadcastTXT() envoie à tous.

Sécurité — déconnexion
Si le WiFi coupe ou si le navigateur est fermé, WStype_DISCONNECTED est déclenché. Sans le standStill() à cet endroit, les servos continueraient la dernière frame de marche indéfiniment — le robot marcherait sans contrôle.

Moteur de marche — tickGait()

PCA9685

Appelée à chaque tour de loop(), elle décide si le moment est venu d'avancer d'une frame de marche. Si la commande est STOP, elle immobilise le robot. Sinon, elle sélectionne la bonne séquence et appelle applyFrame().

C++tickGait() — timer non-bloquant et sélection de séquence
// Calcule le délai entre deux frames selon la vitesse reçue du dashboard
// speed=0   → 400 ms entre chaque frame (très lent)
// speed=100 → 80 ms entre chaque frame  (rapide)
uint32_t gaitDelay() {
  return (uint32_t)map(speed, 0, 100, 400, 80);
}

void tickGait() {
  // Timer non-bloquant : si le délai n'est pas écoulé, on ne fait rien
  if (millis() - lastGaitStep < gaitDelay()) return;
  lastGaitStep = millis();

  // Sélectionne la séquence de marche selon la commande active
  switch (currentCmd) {

    case CMD_FORWARD:
      // GAIT_FORWARD contient 4 frames → modulo 4 pour boucler
      applyFrame(GAIT_FORWARD[gaitFrame % 4]);
      gaitFrame++;
      break;

    case CMD_BACKWARD:
      applyFrame(GAIT_BACKWARD[gaitFrame % 4]);
      gaitFrame++;
      break;

    case CMD_LEFT:
      // Les virages n'ont que 2 frames
      applyFrame(GAIT_LEFT[gaitFrame % 2]);
      gaitFrame++;
      break;

    case CMD_RIGHT:
      applyFrame(GAIT_RIGHT[gaitFrame % 2]);
      gaitFrame++;
      break;

    case CMD_STOP:
    default:
      standStill();
      break;
  }
}

Séquences de marche — GaitFrame

PCA9685

Chaque GaitFrame est un instantané de position : il décrit exactement où doit être chaque hanche et chaque genou des 4 membres à un instant donné. Enchaîner plusieurs frames crée l'illusion du mouvement.

C++Structure GaitFrame et mapping des membres
// Position d'un membre : hanche + genou, en ticks PCA9685
struct LegPos { uint16_t hip; uint16_t knee; };

// Un instantané complet des 4 membres
struct GaitFrame {
  LegPos br;  // Postérieur Droit  → ch0 (LED01) + ch1 (LED02)
  LegPos bl;  // Postérieur Gauche → ch2 (LED03) + ch3 (LED04)
  LegPos fr;  // Antérieur Droit   → ch4 (LED05) + ch5 (LED06)
  LegPos fl;  // Antérieur Gauche  → ch6 (LED07) + ch7 (LED08)
};

// Ticks PCA9685 à 50 Hz (4096 ticks = une période de 20 ms)
// SERVO_MIN=150 ≈ 0°   SERVO_MID=375 ≈ 90°   SERVO_MAX=600 ≈ 180°
// Ces valeurs sont à calibrer selon ton modèle de servo
#define SERVO_MIN  150
#define SERVO_MID  375
#define SERVO_MAX  600

La marche utilise un trot diagonal : deux membres diagonalement opposés bougent ensemble pendant que les deux autres restent en appui. C'est la démarche naturelle des quadrupèdes à vitesse moyenne.

Trot diagonal — vue de dessus du robot Phase 1 : FR + BL lèvent Phase 2 : FL + BR lèvent ┌────────────────────┐ ┌────────────────────┐ │ FL ● FR ↑│ │ FL ↑ FR ●│ │ │ │ │ │ BL ↑ BR ●│ │ BL ● BR ↑│ └────────────────────┘ └────────────────────┘ ● = pied au sol (appui) ↑ = pied levé (avance)
C++Séquence GAIT_FORWARD — 4 frames de trot diagonal
const GaitFrame GAIT_FORWARD[4] = {

  // Frame 0 : FR et BL se lèvent, FL et BR restent en appui
  { {SERVO_MID,      SERVO_MID},        // BR : hanche et genou neutres (appui)
    {SERVO_MID+50,   SERVO_MID-60},    // BL : hanche avance, genou se lève
    {SERVO_MID-50,   SERVO_MID-60},    // FR : hanche avance, genou se lève
    {SERVO_MID,      SERVO_MID} },      // FL : neutre (appui)

  // Frame 1 : FR et BL se posent en avant
  { {SERVO_MID,      SERVO_MID},
    {SERVO_MID-30,   SERVO_MID},        // BL : genou redescend, pied se pose
    {SERVO_MID+30,   SERVO_MID},        // FR : genou redescend, pied se pose
    {SERVO_MID,      SERVO_MID} },

  // Frame 2 : FL et BR se lèvent, FR et BL restent en appui
  { {SERVO_MID+50,   SERVO_MID-60},    // BR : hanche avance, genou se lève
    {SERVO_MID,      SERVO_MID},
    {SERVO_MID,      SERVO_MID},
    {SERVO_MID-50,   SERVO_MID-60} },  // FL : hanche avance, genou se lève

  // Frame 3 : FL et BR se posent en avant
  { {SERVO_MID-30,   SERVO_MID},
    {SERVO_MID,      SERVO_MID},
    {SERVO_MID,      SERVO_MID},
    {SERVO_MID+30,   SERVO_MID} }
};
Comment calibrer les frames
Les deltas comme +50 ou -60 sont des points de départ. Pour les affiner : branche un seul servo, envoie manuellement des ticks via pca.setPWM(ch, 0, valeur) et observe l'angle obtenu. Ajuste ensuite les frames selon la géométrie réelle de tes membres.

Application d'une frame — applyFrame()

PCA9685 I2C

Reçoit un GaitFrame et envoie les 8 positions (4 hanches + 4 genoux) au PCA9685 via I2C. C'est la fonction qui traduit les données en mouvement physique.

C++applyFrame() — envoi de 8 positions servo au PCA9685
void applyFrame(const GaitFrame& f) {
  // Postérieur Droit  — LED01 (ch0) = hanche, LED02 (ch1) = genou
  setServo(SERVO_BR_HIP,  f.br.hip);
  setServo(SERVO_BR_KNEE, f.br.knee);

  // Postérieur Gauche — LED03 (ch2) = hanche, LED04 (ch3) = genou
  setServo(SERVO_BL_HIP,  f.bl.hip);
  setServo(SERVO_BL_KNEE, f.bl.knee);

  // Antérieur Droit   — LED05 (ch4) = hanche, LED06 (ch5) = genou
  setServo(SERVO_FR_HIP,  f.fr.hip);
  setServo(SERVO_FR_KNEE, f.fr.knee);

  // Antérieur Gauche  — LED07 (ch6) = hanche, LED08 (ch7) = genou
  setServo(SERVO_FL_HIP,  f.fl.hip);
  setServo(SERVO_FL_KNEE, f.fl.knee);
}

// Mapping des canaux PCA9685 → constantes définies en haut du fichier
#define SERVO_BR_HIP   0   // ch0 = LED01
#define SERVO_BR_KNEE  1   // ch1 = LED02
#define SERVO_BL_HIP   2   // ch2 = LED03
#define SERVO_BL_KNEE  3   // ch3 = LED04
#define SERVO_FR_HIP   4   // ch4 = LED05
#define SERVO_FR_KNEE  5   // ch5 = LED06
#define SERVO_FL_HIP   6   // ch6 = LED07
#define SERVO_FL_KNEE  7   // ch7 = LED08

Pilotage d'un servo — setServo()

PCA9685 PWM

Envoie une commande PWM à un canal précis du PCA9685. Elle protège les servos en bornant la valeur entre SERVO_MIN et SERVO_MAX — un dépassement mécaniquement dangereux est ainsi impossible.

C++setServo() — envoi PWM sécurisé au PCA9685
void setServo(uint8_t ch, uint16_t ticks) {
  // constrain() empêche d'envoyer une valeur hors des limites mécaniques
  // Un servo forcé hors de sa plage peut brûler son moteur interne
  ticks = constrain(ticks, SERVO_MIN, SERVO_MAX);

  // setPWM(canal, délai_début, délai_fin)
  //   canal       = 0 à 15 sur le PCA9685
  //   délai_début = 0 (impulsion commence au début de la période)
  //   délai_fin   = ticks (nombre de ticks avant la fin de l'impulsion)
  //
  // À 50 Hz : période = 20 ms = 4096 ticks
  //   150 ticks → impulsion de 150/4096 × 20 ms ≈ 0.73 ms ≈ 0°
  //   375 ticks → impulsion de 375/4096 × 20 ms ≈ 1.83 ms ≈ 90°
  //   600 ticks → impulsion de 600/4096 × 20 ms ≈ 2.93 ms ≈ 180°
  pca.setPWM(ch, 0, ticks);
}

Posture neutre — standStill()

PCA9685

Place tous les servos en position SERVO_MID (90°). Appelée au démarrage, à l'arrêt et à la déconnexion du dashboard. C'est la posture de repos du robot — debout, stable, prêt à recevoir des commandes.

C++standStill() — posture neutre tous servos à 90°
void standStill() {
  // Construit un GaitFrame où tous les membres sont en position neutre
  // STAND = { SERVO_MID, SERVO_MID } pour hanche et genou
  applyFrame({ STAND, STAND, STAND, STAND });

  // Remet le compteur de frame à 0 pour que la prochaine commande
  // reparte proprement depuis le début de sa séquence
  gaitFrame = 0;
}

const LegPos STAND = { SERVO_MID, SERVO_MID }; // { 375, 375 }

Lecture du capteur gaz — readMQ9()

MQ-9 ADC

Lit les deux sorties du module MQ-9 et calcule une estimation en ppm de CO. Le calcul suit la courbe caractéristique publiée dans la datasheet du MQ-9, modélisée par une loi puissance log-log.

C++readMQ9() — lecture ADC et calcul ppm CO
SensorData readMQ9() {
  SensorData d;

  // ── Lecture analogique (GPIO34, ADC1) ─────────────────────────
  // analogRead() retourne 0-4095 (résolution 12 bits de l'ESP32)
  // GPIO34 est sur ADC1 → compatible avec le WiFi actif
  d.raw = analogRead(MQ9_ANALOG_PIN);

  // ── Lecture digitale (GPIO32) ─────────────────────────────────
  // LOW = le comparateur interne du module a détecté un dépassement
  // Le seuil est réglable via le potentiomètre bleu du module
  d.alert = digitalRead(MQ9_DIGITAL_PIN) == LOW;

  // ── Conversion en volts ───────────────────────────────────────
  // L'ADC 12 bits de l'ESP32 couvre 0 à 3.3V
  // tension = (raw / 4095) × 3.3
  d.voltage = (d.raw / 4095.0f) * 3.3f;

  // ── Calcul de RS (résistance du capteur) ──────────────────────
  // Le module MQ-9 est un pont diviseur de tension :
  //   VCC ─── RS(capteur) ─── Vout ─── RL(résistance charge) ─── GND
  // D'où : RS = RL × (VCC - Vout) / Vout
  // RL_VALUE = 10 kΩ (valeur typique sur les modules MQ-9)
  if (d.voltage > 0.01f) {
    d.rs = RL_VALUE * (3.3f - d.voltage) / d.voltage;
  } else {
    d.rs = 0;
  }

  // ── Calcul du ratio RS/RO ─────────────────────────────────────
  // RO = résistance du capteur dans l'air pur (à calibrer)
  // Plus le ratio est bas, plus la concentration de gaz est élevée
  d.ratio = d.rs / RO;

  // ── Estimation CO en ppm (courbe datasheet MQ-9) ─────────────
  // La datasheet donne une droite en échelle log-log :
  //   log(ppm) = a × log(RS/RO) + b
  // Soit en linéaire :  ppm = a × (RS/RO)^b
  // Pour le CO : a = 599.65, b = -2.244
  // (valeurs ajustées depuis la courbe graphique de la datasheet)
  if (d.ratio > 0) {
    d.ppm = 599.65f * pow(d.ratio, -2.244f);
  } else {
    d.ppm = 0;
  }

  return d;
}
Calibration obligatoire — la valeur RO
La constante RO (résistance dans l'air pur) varie d'un capteur à l'autre. Pour calibrer : laisse le MQ-9 chauffer 5 minutes en air pur, relève la valeur de d.rs dans le moniteur série, et remplace RO = 10.0 par cette valeur. Sans calibration, les ppm affichées sont indicatives mais pas précises.

Envoi des données au dashboard — broadcastTXT()

WebSocket sortant

Toutes les 2 secondes, l'ESP sérialise les données du MQ-9 en JSON et les diffuse à tous les clients WebSocket connectés simultanément. Le dashboard reçoit ce JSON dans son ws.onmessage et appelle updateSensors().

C++Sérialisation JSON et broadcast WebSocket
if (millis() - lastSensorSend > 2000) {
  lastSensorSend = millis();

  SensorData d = readMQ9();

  // StaticJsonDocument<160> = buffer JSON de 160 octets alloué sur la pile
  // Taille calculée : environ 120 octets pour ce JSON + marge
  StaticJsonDocument<160> doc;

  doc["type"]    = "sensor";
  doc["raw"]     = d.raw;

  // serialized(String(...)) insère une valeur float déjà formatée
  // plutôt que de laisser ArduinoJson choisir le nombre de décimales
  doc["voltage"] = serialized(String(d.voltage, 3)); // 3 décimales
  doc["rs"]      = serialized(String(d.rs,      3));
  doc["ratio"]   = serialized(String(d.ratio,   3));
  doc["ppm"]     = serialized(String(d.ppm,     1)); // 1 décimale
  doc["alert"]   = d.alert;                             // true / false

  String out;
  serializeJson(doc, out); // Convertit le document en String JSON

  // broadcastTXT() envoie à tous les clients connectés
  // sendTXT(num, ...) enverrait uniquement au client numéro "num"
  wsServer.broadcastTXT(out);

  // Log série pour le moniteur PlatformIO
  Serial.printf("[MQ-9] %.1f ppm | alert=%s | CMD=%d speed=%d\n",
    d.ppm, d.alert ? "OUI" : "non", (int)currentCmd, speed);
}
